# 録音アプリ（商談音声日報）：訪問先を選んで対面録音し、日報を見る

営業がスマホで「入力 → 録音 → 日報」と進める Web アプリ（`https://<サービス>/app/`）。
CRM のワークフローから録音用URLを発行する方法（[crm-workflow.md](crm-workflow.md)）と並べて使える。
オンライン商談は、これまでどおり CRM から呼ぶボット（[recall-bot.md](recall-bot.md)）で行う。

| 画面 | できること |
|---|---|
| 入力 | ログイン中の営業担当者を表示。GPS から近くの顧客企業を候補に出す。会社名・住所・担当者名で検索。顧客側の担当者（連絡先）を複数選ぶ（CRM に無い人は名前を足す）。新規顧客は会社名を入れる |
| 録音 | 選んだ訪問先と担当者を確かめて「録音画面を開く」。CRM に商談記録を作り、これまでの録音ページを開く |
| 日報 | 今日の自分の記録と、処理の結果（要約・課題・ニーズ・予算・決裁者・競合・次のアクション・次回期限）。処理中は自動で更新 |

## CRM に書くもの・読むもの

- **書くのは「商談記録」の新規作成だけ**（1件の録音につき1回。処理が終わるとバックエンドが結果を書く）。
  既存のデータ・設定（顧客企業・連絡先・ほかのモジュール・項目・ワークフロー）は変えない
- 作る商談記録の中身：

  | 項目 | 値 |
  |---|---|
  | 商談記録名 | `2026-10-01 株式会社サンプル 訪問`（新規顧客は `（新規）` を付ける。テスト中は先頭に【TEST】） |
  | 商談記録の担当者 | ログインした人 |
  | 取引先 | 選んだ顧客企業（新規顧客は空。処理が終わると状態は「取引先未設定」） |
  | 先方担当者 | 選んだ担当者の名前（「、」区切り。CRM に無い人の名前も入る） |
  | 先方担当者（連絡先） | 選んだ担当者のうち CRM の連絡先（複数選択ルックアップ。その顧客企業の連絡先だけ） |
  | 商談形態 / 取得方法 | 対面 / 対面録音 |
  | 開始日時 | 「録音画面を開く」を押した時刻 |

- **新規顧客は CRM に作らない。** 名前だけ商談記録に残す。あとで営業が CRM で顧客企業を登録し、商談記録の「取引先」に紐づける
- **先方担当者（連絡先）**：連絡先の画面の関連リスト「商談記録」に、その人が出た商談記録が並ぶ。
  商談記録の画面では、紐づいた連絡先が関連リスト（Zoho が付けた名前は「relatedlist」）に並ぶ。
  この項目を作ると、Zoho が連絡先に逆向きの項目と関連リストを足す（2026-10-02 ユーザー了承。連絡先のデータは書き換えない）。
  項目を作る前（docs/crm-setup.md の手順7）は、名前だけを「先方担当者」に書く。紐づけを CRM に断られたときも、
  名前だけで商談記録を作り、録音は止めない
- 読むのは、顧客企業（会社名・住所）と連絡先（姓・名・部署・役職）だけ（読み取りの権限で足りる。発行し直しは要らない）
- 作るときに `"trigger": []` を付けるので、CRM の「録音用URLの発行」のワークフローは動かない

## ログイン（Zoho アカウント）

- 営業は **CRM のアカウント**でログインする（Zoho のログイン画面に移って戻ってくる）。
  CRM の有効なユーザーで、バックエンドがつないでいる組織と同じ人だけが使える
- ログインは**90日**続く（2026-10-02 のユーザーの判断。`app.session_hours` で短くできる）。サーバーには何も保存しない（署名付きの Cookie だけ）
- 長く続く代わりに、**12時間ごとに「今も CRM の有効なユーザーか」を確かめ直す**（バックエンドの接続で `GET /users/{id}`）。
  退職などで CRM のユーザーを無効にすると、次の確認で使えなくなる（ログアウトして、ログインもできない）。
  Zoho に届かないときは止めずに、次の操作でもう一度確かめる
- ログインに使うのは、CRM のユーザーと組織の読み取りだけ（`ZohoCRM.users.READ`・`ZohoCRM.org.READ`）。
  受け取ったトークンは確認に1回使って捨てる。CRM の検索・書き込みはバックエンドの接続で行う
- 自分が作った記録の日報だけ見られる

## GPS の候補

- スマホの位置から住所（市区町村・区・町）を Google Geocoding API で調べ、同じ市区町村の顧客企業を
  「同じ町 → 同じ区 → 同じ市区町村」の順に最大20件出す。距離は測っていない（顧客の住所を位置に変換しない）
- 顧客企業の住所は CRM の「請求先住所」（都道府県・市区町村・番地）を見る。別の項目に住所を入れている場合は
  `field_map.standard` の `account_state` / `account_city` / `account_street` で変える
- 位置・検索語は画面とサーバーの間だけで使い、ログ・URL に残さない
- 画面に「Google Maps を使っています」と出す（Google の利用規約。地図を出さずに結果を表示するときに必要）
- 料金：Geocoding API は月1万回まで無料、その後 1,000回あたり約5ドル（2026-10 時点の検索結果）

## 1. 設定する（Cloud Shell、15分）

コードを入れ替えてから、ログインの設定を足す。

```bash
cd ~/voice-app && git pull && bash scripts/deploy.sh
bash scripts/setup_app_login.sh
```

`setup_app_login.sh` の流れ（何度実行しても壊れない。2回目からは Enter で保存済みの値を使う）:

1. Zoho の API コンソール（US は `https://api-console.zoho.com`）で「ADD CLIENT」→「Server-based Applications」を選び、
   スクリプトが表示する値で作る（Client Name・Homepage URL・Authorized Redirect URIs）。
   「Client Secret」タブの Client ID と Client Secret を貼る（画面には出ない）
   - 貼り付けられるのは最後にコピーした1つだけ。「Client ID をコピー → 貼る → Client Secret をコピー → 貼る」の順に進める
     （スクリプトを動かすコマンドをコピーしたあとは、Client ID をコピーし直す）
   - **Cloud Shell では Ctrl+C を押さない**（コピーではなく中止になる）。止まったら何も保存されていないので、
     ↑ キー → Enter でやり直す。止まったあとの `$` の行に Client ID や Client Secret を貼ると、ふつうのコマンドとして
     画面と履歴に残る（「command not found」と出る）。そのときは下の「画面に出てしまったとき」で作り直す
2. ログインの Cookie の署名鍵を作る（初回だけ）
3. GPS の候補を使うか（`yes` で Google Geocoding API を有効にする。2回目からは、今のキーを使い続けるか作り直すかを聞く）
4. `yes` で、Geocoding API だけに使える API キーを作り（値は画面に出さない）、Secret Manager に保存して、
   Cloud Run の設定に `app` を足す（ほかの設定・`DRY_RUN` は変えない）。キーを作り直したときは、切り替わったあとで
   古いキーを削除する。`no` なら何も作らず、何も保存しない
5. 録音アプリの URL が表示される（`https://<サービス>/app/`）。途中で gcloud が出す `…<数字>.asia-northeast1.run.app`
   の URL も同じサービスだが、ログインはこのスクリプトが出す URL でしか通らない（Zoho に登録した戻り先の URL のため）

### 画面に出てしまったとき（キーや Client Secret の作り直し）

画面写真やコマンドの履歴に残った値は、作り直して古い値を使えなくする。

- **地図の API キー**（`AIza…`）：`bash scripts/setup_app_login.sh` を実行し、Client ID・Client Secret は Enter、
  GPS は `yes`、「作り直すなら yes」に `yes`、保存に `yes`。新しいキーを作って Cloud Run を切り替えてから、古いキーを削除する
  （古いキーは30日以内なら `gcloud services api-keys undelete <ID>` で戻せる）。このキーは Geocoding API にしか使えないので、
  悪用されても住所検索の料金がかかるだけ
- **Zoho の Client Secret**：API コンソールでそのクライアントを開き、Secret を作り直す（見当たらなければクライアントを削除して、
  同じ値で作り直す。この場合は Client ID も変わる）。スクリプトを実行し、変わった値だけ貼る（変わっていないほうは Enter）

## 2. 使ってみる（スマホ、10分）

1. スマホの Chrome（iPhone は Safari でも可）で録音アプリの URL を開き、「Zoho でログイン」から CRM のアカウントでログインする
2. 入力：「GPSから訪問先候補を取得」→ 位置情報の利用を許可 → 訪問先を選ぶ（見つからなければ顧客検索・新規顧客）
3. 「担当者を選択」で担当者にチェック（CRM に無い人は名前を追加）→「担当者を決定」→「録音へ進む」
4. 録音：「録音画面を開く」→ 録音ページで録音する（いつもの録音ページ。下に「入力・録音・日報」のタブが出る）
5. 録音終了 → 送信が完了したら「日報を見る」。数分で要約などが出る（自動で更新）
6. CRM で商談記録を開き、担当者・取引先・先方担当者・要約が入っていることを確かめる

## うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| 「このクライアントでは録音アプリを使えません」 | `setup_app_login.sh` をまだ実行していない（Cloud Run の設定に `app` が無い） |
| スクリプトで「Client ID の形ではありません」が続く | 最後にコピーしたもの（スクリプトを動かすコマンドなど）が貼られている。Zoho の画面で Client ID をコピーし直して貼る |
| スクリプトが止まり、貼った値に「command not found」 | Ctrl+C でスクリプトが止まっていた（何も保存されていない）。↑ キー → Enter でやり直し、貼った Client Secret は作り直す（上の「画面に出てしまったとき」） |
| 最初のログインで「ログインの途中で時間が過ぎました」と出る（もう一度押すと通る） | `…<数字>.asia-northeast1.run.app` の URL で開いた（Zoho から戻るのはスクリプトが出した URL のほう）。スクリプトが出した URL をブックマークして使う |
| Zoho の画面で「Invalid Redirect Uri」 | API コンソールのクライアントの Authorized Redirect URIs が違う。スクリプトが表示した `…/auth/callback` と同じにする |
| 「この CRM のユーザーではありません」 | 別の会社・別の DC の Zoho アカウントでログインした。会社の CRM のアカウントでログインし直す |
| 「API の利用（Zoho CRM API Access）が許可されていません」 | CRM のプロファイルの権限。管理者が 設定 → セキュリティ管理 → プロファイル で「Zoho CRM API Access」を許可する |
| 「ログインの途中で時間が過ぎました」 | Zoho の画面で10分以上たった、別のブラウザで開いた、など。もう一度ログインする |
| GPS 状態が「位置情報の利用が許可されていません」 | iPhone は 設定 → プライバシーとセキュリティ → 位置情報サービス で Safari / Chrome を「使用中のみ」にする |
| GPS の候補が出ない | 顧客企業の住所（市区町村）が CRM に入っていない、または別の項目に入っている。顧客検索を使う |
| 日報が「録音待ち・送信待ち」のまま | 録音を終了していない、または送信が終わっていない。録音ページに戻って「録音終了」を押す |

## まだ無いもの

- 日報の内容をアプリから直す（いまは CRM で直す）
- 新規顧客を CRM に登録する（CRM の既存のデータに触れない決まりのため、名前だけ残す）
- 距離での並べ替え（顧客の住所を位置に変換して保存する仕組みが要る）
