# 動画の解析（業務システムの画面の説明動画 → 商談記録）

業務システム（生産管理など）を操作しながら説明した動画を Gemini で読み、画面・項目・操作・説明を場面ごとに
こと細かく書き出して、動画1本ごとに「商談記録」を1件作る。システムを作り直す（リプレイスする）ときの要件を決める資料にする
（書き出したものを Claude.ai に、ほかの資料と一緒に渡してまとめてもらう想定。2026-11-03 ユーザーの依頼）。

- 使えるのは、クライアントの `features.video_analysis` が true のクライアントだけ（`client_mode.sh --video-on`。先にデプロイ）
- 書き込むのは「商談記録」だけ（作成。同じ動画の記録があれば更新）。全文の添付は `features.transcript_attachment` が true のとき
- 動画は GCS に置き、処理が終わったら消す（DRY_RUN のときは消さない）。置いたまま処理しなくても、バケットのライフサイクルで1日で消える
- 動画は GitHub を通さない（リポジトリが公開のため）。Actions のログには件数・状態だけが出る

## 使い方（ふだんはこれだけ。Cloud Shell も GitHub も使わない）

1. 録音アプリ（`/app/`）に Zoho でログインし、「動画の解析」（`/app/videos.html`）を開く
   （録音アプリの入力画面にリンクが出る。`features.video_analysis` が true のクライアントだけ）
2. 動画を選んで「アップロードして解析」。動画はブラウザから GCS に直接上がり（署名付き URL。6時間有効・1本 5GB まで）、
   上がり終わった動画から順に解析を依頼する（`POST /api/app/videos/upload-url` → GCS へ PUT → `POST /api/app/videos/analyze`）
3. 同じ画面の「解析の状況」で、動画解析の商談記録の状態を見る（解析中があれば 30 秒ごとに更新）

置き場所は `videos/<クライアント>/<ファイル名>`（ファイル名から、パスの区切り・制御文字・`#?[]*'"%` を除く）。

## 流れ

1. 動画が GCS の `videos/<クライアント>/` に置かれる（上の画面から。Cloud Console から置いた動画は
   ops（`command=video`・`client`・`count`）でまとめて依頼できる → `/internal/video-batch` が置いてある動画ごとに
   `/internal/video-analyze` を積む（45 秒ずつずらす））
2. 解析を積む（画面からは上がり終わった動画ごとに。同じ動画を 10 分以内に二重には積まない）
3. 動画1本ごとに（`app/videos/analysis.py`）
   - 長さを ffprobe で調べる（署名付き URL。URL はログに出さない）
   - 10 分ずつ（`VIDEO_WINDOW_SECONDS`）Gemini に `gs://` のまま読ませ、場面ごとに書き出す（`prompts/video_describe.md`）。
     前の範囲の終わりを手がかりに渡し、画面名の表記をそろえる。出力が切れたら範囲を半分にして読み直す（1 分まで）
   - 書き出したものから、要約・出てきた画面・機能・今の課題・要件の候補・確かめることを作る
     （`prompts/video_summarize.md`・`prompts/video_schema.json`）
   - 商談記録を1回で書く。名前は「動画解析 <ファイル名>」、分類は「動画解析」
   - 動画を消す

## 商談記録のどこに入るか

| 項目 | 中身 |
|---|---|
| 要約 | 動画の要約、出てきた画面の一覧、機能・使い方 |
| 課題 | 今の課題（困っている・手作業・Excel で補っていること） |
| ニーズ | 要件の候補（新しいシステムで引き継ぐ・求められること） |
| 次のアクション | 動画だけでは分からず、確かめる必要があること |
| 文字起こし全文（1・2） | 場面ごとの記録（64,000 文字を超えた分は添付ファイルで読む） |
| 添付ファイル | `動画解析_<ファイル名>.txt`：上の全部と、場面ごとの記録の全文（Claude.ai に渡すのはこれ） |

ファイル名を手がかりに同じ動画の記録を探すので、別の動画には別のファイル名を付ける。解析済み（完了）の動画を置き直しても、
`force` を付けなければやり直さない（動画は残るので、1日で消える）。

## 設定（Cloud Run の環境変数。変えなくても動く）

| 変数 | 既定 | 中身 |
|---|---|---|
| `VIDEO_WINDOW_SECONDS` | 600 | 1回に読ませる長さ（秒） |
| `GEMINI_VIDEO_FPS` | 1.0 | 1秒あたりに読むコマ数（画面の切り替えが速くて読み落とすなら上げる。費用も上がる） |
| `GEMINI_VIDEO_MEDIA_RESOLUTION` | （空：モデルの既定） | `low` / `medium` / `high`。小さい文字が読めなければ `high` |
| `GEMINI_THINKING_VIDEO` | low | 考える量 |

## 費用

初回の1本で `usage` を見て実測する（映像のトークンは音声より多い。docs/unverified-apis.md の M11）。
解析は `video_describe`（動画を読む）と `video_summarize`（まとめる）の2つの処理として集計される。
