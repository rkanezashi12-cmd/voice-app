# 商談ごとの WorkDrive フォルダ（マルサン木型）

商談を作ると、Zoho WorkDrive に顧客企業のフォルダと、その下に商談のフォルダを自動で作り、商談のフォルダの URL を
商談の項目「WorkDriveフォルダ」に書く（2026-11-23 ユーザーの指示。前回の打ち合わせで藤井さんに「来月までに」と約束したもの）。

- 作り方は2つ（どちらか、または両方）。バックエンド（Cloud Run）は使わない
  - **ボタン「フォルダを作成」**（2026-11-23 ユーザーの指示）：商談の画面でボタンを押すと作り、フォルダを新しいタブで開く。
    すでに作ってある商談では、作らずにそのフォルダを開く（[crm/create_workdrive_folder_button.dg](../crm/create_workdrive_folder_button.dg)。手順4B）
  - **ワークフロー**：商談を作ったとき（顧客企業名があれば）自動で作る（[crm/create_workdrive_folder.dg](../crm/create_workdrive_folder.dg)。手順4・5）
  - 2つの関数は同じ処理（直すときは両方直す）。同じ商談で両方が動いても、二重には作らない
- フォルダの階層

  ```
  <チームフォルダ>（下の手順1で作る）
  └─ <顧客企業名>_<顧客企業の ID>      … 同じ企業の ID のフォルダがあれば作らずに使う
      └─ <商談名>_<商談の ID>          … この URL を商談の「WorkDriveフォルダ」に書く
  ```

  - 企業フォルダは名前の末尾の「_<顧客企業の ID>」で探す（あとで企業名を変えても、同じフォルダに入る）
  - 名前に使えない記号（/ : * ? < > |）は全角の「＿」にする
- CRM に書くのは、商談に新しく足す項目「WorkDriveフォルダ」だけ（2026-11-23 ユーザー了承：商談への項目の追加と、その項目への書き込み。
  削除はしない）。ほかの項目・レコードは変えない。関数の書き込みはワークフローを起動しない
- WorkDrive ではフォルダを作るだけ。フォルダ・ファイルの削除や名前の変更はしない
- 顧客企業名が空の商談は作らない。あとで顧客企業名を入れて保存すると作る（ワークフローの条件）
- すでにある商談は、次に編集して保存したときに作る（URL が空の商談だけ）。まとめて作りたいときは別に相談

## 手順（画面の作業。最初の1回だけ）

### 1. WorkDrive にチームフォルダを作る

1. Zoho WorkDrive（https://workdrive.zoho.com）を開き、チームフォルダを新しく作る（例：「商談フォルダ」）。
   営業のメンバーをチームフォルダのメンバーにする（メンバーでない人は、商談の URL を開けない）
2. 作ったチームフォルダを開き、ブラウザの URL の末尾の英数字（チームフォルダの ID）を控える

### 2. 商談に項目を足す（CRM の画面）

設定 →「モジュールと項目」→「商談」→ レイアウト（標準）を開き、

1. 「URL」の項目を足す。項目名「WorkDriveフォルダ」
2. 保存したあと、設定 →「開発者向け機能」→「API」→「API 名」→「商談」で、この項目の API 名を `WorkDrive_Folder` にする
   （自動で付いた名前のままなら、関数の設定 `F_FOLDER_URL` をその名前に直す）
3. 商談の顧客企業の項目（画面の名前「顧客企業名」）の API 名が `Account_Name` であることを同じ画面で確かめる
   （違えば関数の設定 `F_ACCOUNT` を直す）

### 3. WorkDrive への接続を作る（CRM の画面）

設定 →「開発者向け機能」→「接続」→「接続を作成」

1. サービス：「Zoho WorkDrive」
2. 接続名：`workdriveconn`（**接続のリンク名がこの名前になっていること**。関数の中に直接書いている。マルサン木型は 2026-11-24 にこの名前で作成）
3. スコープ：`WorkDrive.files.READ`（一覧）と `WorkDrive.files.CREATE`（フォルダの作成）の2つ（公式ドキュメントで確認）
4. 「作成して接続」→ 手順1のチームフォルダに入れる Zoho アカウント（管理者）で承認する

### 4. 関数を作る（ワークフロー用。自動で作るとき）

設定 →「開発者向け機能」→「関数」→「新しい関数」

1. 関数名 `create_workdrive_folder`、表示名「WorkDrive フォルダの作成」、カテゴリー「自動化（Automation）」
2. 「引数を編集」で、引数 `deal_id`（文字列 / String）を1つ足す
3. `{` と `}` の間を、[crm/create_workdrive_folder.dg](../crm/create_workdrive_folder.dg) の `{` と `}` の間で置き換える
4. 設定の `PARENT_FOLDER_ID` の `<チームフォルダの ID>` を、手順1で控えた ID にして保存する

### 4B. ボタン「フォルダを作成」を作る

設定 →「モジュールと項目」→「商談」→「リンクとボタン」→「新しいボタン」

1. ボタン名「フォルダを作成」。表示する場所：レコードの詳細ページ
2. 動作：「関数」→「新しい関数を作成」（関数の種類はボタン）。関数名 `create_workdrive_folder_button`、表示名「フォルダを作成」
3. 「引数を編集」で、引数 `deal_id`（文字列 / String）を1つ足す。エディタの1行目が
   `string button.create_workdrive_folder_button(String deal_id)` になる
4. `{` と `}` の間を、[crm/create_workdrive_folder_button.dg](../crm/create_workdrive_folder_button.dg) の `{` と `}` の間で置き換え、
   設定の `PARENT_FOLDER_ID` を手順1の ID にして保存する
5. **引数の設定で、`deal_id` に「商談 Id」を割り当てる**（割り当てが無いと、押しても「引数 deal_id … 割り当てられていません」と出る）
6. ボタンを使うプロファイルを選んで保存する
7. 商談を開き、「フォルダを作成」を押す。「WorkDrive にフォルダを作成しました」と出て、新しいタブでフォルダが開けば成功
   （タブが開かないときは、ブラウザのポップアップのブロックを確かめる）

ボタンだけを使うなら、手順4・5（ワークフロー）は要らない。

### 5. ワークフローを作る（自動で作るとき）

設定 →「自動化」→「ワークフロールール」→「ルールを作成」

1. モジュール「商談」、ルール名「WorkDrive フォルダの作成」
2. 実行のタイミング：「作成または編集」。「繰り返し実行する」にチェック
3. 条件：「WorkDriveフォルダ」が空 **かつ**「顧客企業名」が空ではない
4. 即時のアクション：「関数」→「WorkDrive フォルダの作成」
5. **引数の設定で、`deal_id` に「商談 Id」を割り当てる**（忘れると、エラーも出ずに何も起きない）
6. 保存する

### 6. 試す

1. 顧客企業名を入れた商談を1件作る（テストなら商談名の先頭に【TEST】）
2. 数秒後に商談を開き直し、「WorkDriveフォルダ」に URL が入っていることを確かめる。URL を開くと商談のフォルダが出る
3. 同じ顧客企業でもう1件作り、WorkDrive で企業フォルダが1つのまま、その下に商談フォルダが2つになることを確かめる
4. 関数のログ（設定 →「開発者向け機能」→「関数」→「WorkDrive フォルダの作成」）に `===== SUCCESS` が出る。
   `STEP3 生レスポンス=` と `STEP4 生レスポンス=` の行を送る（応答の形を記録するため。下の「未確認」）
5. 商談の URL を開き、WorkDrive の商談フォルダが開くことを確かめる（URL の形は下の「未確認」）

## うまくいかないとき

| ログ | 原因と対処 |
|---|---|
| 何も出ない | ワークフローの条件・引数の割り当て（手順5）を確かめる |
| `deal_id が空` | 手順5の 5（引数の割り当て）が無い |
| `PARENT_FOLDER_ID … が未設定` | 手順4の 4 |
| `企業フォルダの一覧を読めませんでした` | 接続（手順3）の名前・スコープ、チームフォルダの ID、承認したアカウントがチームフォルダのメンバーか |
| `商談に URL を書けませんでした` | 商談の項目の API 名（手順2） |
| `企業フォルダを作れませんでした`／`商談フォルダを作れなかったか、URL を読めませんでした` | すぐ上の `生レスポンス=` を見る。`F7004`（スコープ不足）なら手順3。作った直後のフォルダが一覧にまだ出なかっただけなら、商談をもう一度保存すると、作ったフォルダを見つけて URL を書く（二重には作らない） |
| URL を開くと「アクセス権がない」 | 開いた人がチームフォルダのメンバーではない（手順1） |

## WorkDrive の API（公式ドキュメントで確認、2026-11-23）

- 作成：`POST https://www.zohoapis.com/workdrive/api/v1/files`、本文 `{"data":{"attributes":{"parent_id":"<親の ID>","name":"<名前>"},"type":"files"}}`、
  スコープ `WorkDrive.files.CREATE`。`parent_id` はフォルダかチームフォルダの ID。名前は 200 文字まで。
  同じ名前があると `R002`（Folder with same name exists）、親の ID が違うと `R602`、スコープ不足は `F7004`
- 一覧：`GET https://www.zohoapis.com/workdrive/api/v1/files/{ID}/files`、スコープ `WorkDrive.files.READ`。
  `page[limit]` は最大 50、`page[offset]` で始まりの位置、`filter[type]=folder` でフォルダだけ。
  応答の `data[].id`・`data[].attributes.name`・`is_folder`・`permalink`。中身が空なら 204（本文なし）
- 関数は、作成の応答の形に頼らず、作ったあとにもう一度一覧を読んで ID と URL（`permalink`）を取る
