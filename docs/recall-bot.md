# オンライン商談のボット参加（入口A：Recall.ai）

商談記録の「取得方法」を「ボット」にして「会議URL」を入れると、CRM のワークフローが関数を呼び、
バックエンドが Recall.ai の録音ボットを予約する。ボットは開始日時の1分前（空ならすぐ）に会議に参加し、
会議が終わると、文字起こし（Recall.ai）→ 補正・要約（Gemini）→ 商談記録の更新 → 録画の削除 まで自動で進む。

- 2026-10-01 に、マルサン木型の本番組織と Google Meet（個人アカウントで主催）で、予約から録画の削除まで
  通しで動くことを確認した（下の「記録」）。Zoom / Teams はまだ試していない
- 社内デモ・検証用と、デスクトップアプリを入れられない場合の予備。お客様の本番はデスクトップ録音（入口C）が標準
- ボットは会議の参加者として見える（表示名は手順1で決める）。待機室があれば主催者が入室を許可する
- `DRY_RUN=true` でもボットは会議に参加する（Recall.ai の料金がかかる）。止まるのは CRM への書き込みと録画の削除だけ
- Recall.ai の公式ドキュメントはこの作業環境から開けない。実物で確かめたこと・まだのことは [unverified-apis.md](unverified-apis.md)

## 事前に用意するもの

- Recall.ai のアカウント（リージョンは東京 ap-northeast-1）。料金は録音した時間に応じてかかる
  （ダッシュボードの「Explorer」でボットごとの利用時間が見られる。2026-10-01 のテストは 2分50秒）
- テスト用の会議（Google Meet / Zoom / Teams）。自分が主催者になれるもの

料金の目安（Recall.ai の料金ページの検索結果の抜粋。2026-10-01 時点。全文は開けていない）：録音 1時間 $0.50
（ボットは参加を始めてから抜けるまで。待機室の時間も含む）＋ 文字起こし 1時間 $0.15。月額の最低料金は無い。
2025-06-12 以降に作ったアカウントは録画を無期限に残すのが既定で、7日を超えると保存料がかかる
（バックエンドは処理が終わると録画を削除する。処理が失敗した録画は残る）。

## 会議ツールごとの注意（検索結果の抜粋。Google Meet 以外はまだ試していない）

| 会議ツール | 注意 |
|---|---|
| Google Meet | 主催者が入室を承諾する（2026-10-01 に確認）。組織の参加者だけに絞った会議には入れない |
| Zoom | 2026-03 から、他のアカウントが主催する会議にボットを入れるには、Zoom の審査を通った自社の Zoom アプリと、それを許可した人が会議に入っていること（OBF）が必要。主催者の録音の許可も要る。お客様側が主催する Zoom ではボットは難しい |
| Teams | 2026-05 から、ボットは見分けられて待機室で止められる（入室の許可が要る）。2026-10 から、相手の会社の管理者がボットを締め出す設定を使える。匿名の参加を禁止している会社の会議には入れない |

ボットが入れない会議は、デスクトップ録音（入口C）なら録れる（会議にボットが出ない）。

## 1. Recall.ai をバックエンドにつなぐ（Cloud Shell、10分）

```bash
cd ~/voice-app && git pull && bash scripts/setup_recall.sh
```

画面の案内どおりに進める（何度実行しても壊れない。ボットは作らない。`DRY_RUN` は変えない）:

1. API キーを貼る（東京リージョンのダッシュボードの「Developers」で作ったもの）。スクリプトが読み取りの問い合わせで確かめる
2. 表示された URL（`…/webhooks/recall`）を、Recall.ai のダッシュボードの左の「Webhooks」→「Add Endpoint」で送り先として追加する
   - Description は空でよい
   - Subscribe to events で「bot」と「sdk_upload」にチェックする（1つ以上選ばないと作れない。ほかは要らない）
   - 作った送り先の画面にある Signing Secret（`whsec_` で始まるもの）をコピーして、スクリプトに貼る
3. ボットの表示名を決める（そのまま Enter で「議事録ボット（録音中）」。矢印キーで文字を直せる）
4. 保存の確認で `yes`。Secret Manager に保存し、Cloud Run の設定に `recall` を足す（Zoho などほかの設定は変えない）
5. テスト送信（任意。飛ばしてよい）。手順3のテストで、状態が「参加待ち」「録音中」に変われば署名は合っている

2回目からは、保存済みの API キー・シークレット・表示名を、そのまま Enter で使える（表示名だけ変えるときなど）。

## 2. CRM の関数とワークフロー（画面、10分）

録音用URLの発行（[crm-workflow.md](crm-workflow.md)）と同じ流れ。CRM の変数（`meeting_notes_url` / `meeting_notes_api_key`）は
作成済みのものをそのまま使う。作るのは新しい関数とワークフローだけで、既存の設定は変えない。

関数：設定 →「開発者向け機能」→「関数」→「新しい関数」

1. 関数名 `create_bot`、表示名「ボットを予約」、カテゴリー「自動化（Automation）」で作成する
2. エディタ上部の「引数を編集」で、引数 `rec_id`（種類：文字列 / String）を1つ追加する。
   エディタの1行目が `void automation.create_bot(String rec_id)` になる
3. `{` と `}` の間を、[crm/create_bot.dg](../crm/create_bot.dg) の `{` と `}` の間（コメントから最後の `info` まで）で置き換えて「保存」する

ワークフロー：設定 →「自動化」→「ワークフロールール」→「ルールを作成」

1. モジュール「商談記録」、ルール名「ボットの予約」
2. 実行のタイミング：レコードの操作 →「作成または編集」。「繰り返し実行する」にチェック
3. 条件：「取得方法」が「ボット」と等しい **かつ**「会議URL」が空ではない **かつ**「Recall ID」が空
4. 即時のアクション：「関数」→ 既存の関数から「ボットを予約」を選ぶ
5. **引数の設定で、`rec_id` に「商談記録 Id」を割り当てる**（`#` から 商談記録 → 商談記録 Id）。
   これを忘れると、エラーも出ずに何も起きない
6. 保存して関連付け、ルールを保存する

録音用URLの発行のワークフローは取得方法が「対面録音」のときだけ動くので、ボットの商談記録では動かない。

予約に成功するとバックエンドが「Recall ID」を書くので、同じ商談記録を編集してもボットを二重に予約しない
（`DRY_RUN=true` の間はバックエンドが書かないので、編集して保存するたびに予約し直してしまう。テストは `DRY_RUN=false` で行う）。
予約に失敗したときは状態が「失敗」になり、「エラー内容」に理由が入る。会議URL などを直して保存すると、もう一度予約する。

## 3. 試す（テスト用の会議で 10分ほど）

1. テスト用の会議を始める（自分が主催者）。Google Meet なら「新しい会議を作成」→「会議を今すぐ開始」で、会議の URL をコピーする
2. CRM で商談記録を作る：商談記録名「【TEST】ボットの確認」、取得方法「ボット」、会議URL（コピーした URL）、
   開始日時は空（空ならボットはすぐに参加する）
3. 商談記録を開き直す。状態が「予約済」になり、「Recall ID」に値が入っていれば予約できている
   （関数のログは 設定 →「開発者向け機能」→「関数」→「ボットを予約」。`===== SUCCESS bot_id=…` が出る）
4. 10秒〜1分でボットが参加を求めてくる。入室を許可する（Zoom で録音の許可を求められたら、それも許可する）
5. 商談記録を再読み込みして、状態が「録音中」になっていることを確かめる。
   「予約済」のままなら Recall.ai からの通知が届いていない（下の「うまくいかないとき」）
6. 1〜2分話してから（構造化項目まで確かめるときは [test-conversation.md](test-conversation.md) の台本を2人で読み上げる）、
   自分が会議から退出する。ボットは参加者がいなくなると数秒で自動で抜ける
7. 数分待って商談記録を開く（2026-10-01 はボットが抜けてから2分半）。状態が「完了」（取引先が空なら「取引先未設定」）になり、
   要約・構造化項目・文字起こし全文（参加者名つき）が入っていれば成功

状態は 予約済 → 参加待ち（待機室）→ 録音中 → 文字起こし中 → 完了 / 取引先未設定 と変わる。
失敗すると「失敗」か「参加失敗」になり、「エラー内容」に理由が入る。

途中経過や時間は、Cloud Shell で見られる（予約から1時間を超えたときは `bash scripts/process_logs.sh 180`）:

```bash
cd ~/voice-app && bash scripts/process_logs.sh
```

| イベント | 意味 |
|---|---|
| `bot.reserved` | ボットを予約した |
| `webhook.received` → `recall.event_parsed` | Recall.ai から状態の通知が届いた（`Recallのイベント` に種類、`サブコード` に理由） |
| `recall.status_written` | 商談記録の状態を書いた（`waiting` が参加待ち、`recording` が録音中） |
| `recall.event_parsed`（`bot.done`） | ボットが会議から抜けた。録音後の処理を積む |
| `recall.transcript_requested` → `pipeline.waiting_transcript` | Recall.ai に文字起こしを依頼し、終わるのを待っている（2分おきに確認） |
| `recall.transcript_loaded` | 文字起こしを取得した（`文字数` に文字数） |
| `gemini.generated`（2回） | `処理` が correct・summarize |
| `crm.updated` | 商談記録を更新した（`項目` に書いた項目） |
| `recall.media_deleted` | Recall.ai の録画・音声を消した |
| `pipeline.finished` | `状態` が `done` |

予約の時刻（任意）：開始日時を15分以上先にして商談記録を作ると、ボットはその1分前に参加する。
開始日時が10分以上先なら Recall.ai の予約になり、すぐ参加させるときのボットの空き不足（下の 507）が起きない。

## 4. 詳しく調べるとき（任意）

ボットの様子は、Recall.ai のダッシュボードの「Explorer」で、商談記録の「Recall ID」のボットを開いても見られる。
処理が終わると Status が「Media Expired」になり、録画・文字起こしは表示されない（バックエンドが削除したため）。

応答の形を Cloud Shell で見るとき（読み取りだけ。値は ID・状態・日時だけを表示し、会議 URL・発言は出さない）:

```bash
cd ~/voice-app && bash scripts/recall_inspect.sh bot 9d349b62-3f21-4afc-8d21-80593c7e3724
```

最後の部分は、調べたい商談記録の「Recall ID」の値に置き換える。**`< >` は付けない**
（`<Recall ID>` のように `< >` ごと貼ると `syntax error near unexpected token 'newline'` になる）。
表示の `recordings[0].id` で、録音も見られる（`bash scripts/recall_inspect.sh recording <その値>`）。

## うまくいかないとき

| 症状・ログ | 原因と対処 |
|---|---|
| 関数のログに何も出ない | ワークフローが動いていない。条件（取得方法・会議URL・Recall ID）とタイミングを確かめる |
| `rec_id が空です` | 手順2（ワークフロー）の 5 の引数の割り当てが無い |
| `応答コード=401` | API キーの誤り。`rotate_api_key.sh` で出した最新のキーを CRM の変数に貼り直す |
| `応答コード=422` | 会議URL が Zoom / Teams / Google Meet の https の URL ではない。または開始日時の形が違う（ログの `開始日時=` の表示を送る） |
| `応答コード=502` | Recall.ai が予約を断った。商談記録の「エラー内容」に Recall.ai が返した理由が入る |
| エラー内容に「すぐ参加できるボットの空きがありませんでした」 | Recall.ai の 507（すぐ参加させるボットの空き不足）。開始日時を10分以上先にして保存し直す |
| 会議中なのに状態が「予約済」のまま、`webhook.` の行も出ない | Recall.ai からの通知が届いていない。Webhooks の送り先 URL・イベント（bot）・シークレットを確かめ、`setup_recall.sh` をもう一度実行する |
| 状態が「参加失敗」 | 待機室で入室を許可しなかった、など。「エラー内容」を確かめる |
| `pipeline.waiting_transcript` が続く | Recall.ai の文字起こしが終わっていない。最大1時間（2分おきに30回）待って、それでも終わらなければ失敗にする |
| `pipeline.failed` に「録音データがありません」 | ボットが会議に入れなかった |

## まだ無いもの（次の段階）

- 予約のあとに開始日時を変えても、ボットの時刻は変わらない（予約し直す仕組みがない）
- 予約を取り消す操作がない（会議の主催者がボットを入室させなければ録音されない）
- すぐ参加させるボットの空き不足（507）は、数秒の再試行しかしない（Recall.ai は30秒おきに最大10回を勧めている）
- 文字起こしの言語は日本語に固定（Cloud Run のクライアント設定の `recall.transcript_request`）
